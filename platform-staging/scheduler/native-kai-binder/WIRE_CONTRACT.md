# Terminal coordinator transport contract v1

This is the transport envelope for the Go bridge and Root-owned protected Python coordinator. It does not change the SDK allocation ACK, registry or v1 enrollment schemas pinned to0451fd9. Every method is an internal authenticated HTTPS POST to the explicitly configured coordinator origin, with no redirects. There is no human-token, unauthenticated, browser-selected authority, insecure TLS or cross-origin fallback.

Configuration is disabled by default and must supply the exact coordinator base URL, authority namespace, a private projected signed internal ServiceAccount token file and trusted CA file. Root's server must verify the actual signed token and exact configured TokenReview audience, current ServiceAccount UID and current SubjectAccessReview authorization, never trust claims supplied in an envelope or a Pod annotation. No production identity, URL, token or CA is selected by this artifact. Token loading occurs only with explicit enablement. Go requests do not send raw error messages or central expected documents supplied by a caller.

All requests are closed JSON objects with `protocol:"cps-native-kai-terminal/v1"`, `operation` matching the endpoint suffix, and a fresh canonical UUID `request_id`. Responses echo those three fields exactly and use only the method-specific fields below. Public transport fields such as `fence_id` identify a retained server execution fence; they are not Kubernetes metadata fields or native cap claims. A successful HTTP status is200; size is bounded to1MiB and unexpected fields/status/authentication/redirects fail closed. Non-idempotent retries are not automatic. The server must make repeated exact `prepare` for the same PodUID/attempt/generation count once and preserve the existing immutable ACK.

The fixed suffix is `/api/native-kai/v1/<operation>` appended to a configured HTTPS origin (base URL has no path/query/fragment). Both sides use these exact operations and shapes:

| Operation | Additional request fields | Additional response fields |
|---|---|---|
| `prepare` | `pod`, `node`, `bind_request`, `binding_state` | `fence_id`, `ack` |
| `current` | `fence_id`, `pod`, `node`, `bind_request`, `binding_state`, `ack` | none |
| `binding` | `fence_id`, `binding` | none |
| `accepted` | `fence_id`, `binding` | none |
| `close` | `fence_id` | none |
| `hold` | `pod_uid`, `reason_code:"custody-required"` | none |
| `cleanup-maps` | `pod_uid` | `maps` |
| `reservation-delete` | `reservation` | `may_delete` (boolean) |

`pod`, `ack` and `reservation` references are exactly `{namespace,name,uid,resourceVersion}`; `node` is exactly `{name,uid,resourceVersion}`; `bind_request` is exactly `{namespace,name,uid,resourceVersion,generation}`. `binding_state` is exactly `{binding_pod_annotations:<string-map>,reserved_gpu_ids:<string-list>}` from actual upstream BindingState under the authenticated binder identity. UUIDs and versions are actual current identities, not generation values inferred from ConfigMaps. `binding` is the existing exact closed SDK `v1/Binding` object with PodUID/currentRV and NodeUID. `prepare.ack` is the actual complete immutable ConfigMap readback; `cleanup-maps.maps` is the two exact actual old-Pod-owned ConfigMap snapshots after cleanup authorization. No new ACK JSON fields are introduced.

`prepare` must re-read full raw API objects and current central policy/grant/workspace/attempt authority, check the compiler contract and staged protected registry/maps, serialize pool accounting, freeze maps, publish/read back native v1 enrollment and ACK, and retain a writer fence associated with an opaque canonical UUID `fence_id`. A marker or supplied reference alone is never authority. The caller does not submit an expected enrollment or capacity list. The coordinator derives those from its own existing authoritative state. Caller references and BindingState must match actual current readbacks and the fixed approved physical UUID. Full raw API JSON preserves SDK spec/metadata hashing and numeric semantics; re-encoding typed Go snapshots is insufficient.

`current` re-reads all objects plus registry/map/enrollment/epoch/central generations and runs the full SDK current-allocation and immutable ACK validators under that same retained fence. `binding` runs the existing exact SDK Binding validator and keeps the fence held through actual API Binding. `accepted` independently observes the same actual PodUID and strict future-B spec; it records only accepted Binding, never CRI/cgroup/cap sealing. Unknown/lost Binding results must remain durably counted and held. BindRequest and Pod status updates must not happen while the terminal generation is being frozen.

`hold` must be idempotent and durably retain reservations/capacity/maps for that exact PodUID, including unknown outcomes and already-bound Pods. Its signed internal identity must authorize the original attempt; it cannot create a new enrollment or resource grant. `close` releases only the writer execution fence, never resource custody. It must refuse release unless accepted Binding or durable Hold is recorded. Lost transport responses/process exits must not time-expire capacity or cleanup custody. Root's supervisor/reconciliation path owns recovery of abandoned fences.

`cleanup-maps` must independently prove exact old PodUID absence and actual native-zero cleanup before returning those exact known map snapshots. Same-name replacement is never old-Pod evidence. The Go binder additionally verifies each current map UID/RV/name/owner and uses UID/RV deletion preconditions. Private authority ACK/registry/enrollment objects remain retained according to coordinator policy; this method cannot delete research files/PVCs.

`reservation-delete` must validate the actual reservation UID/RV and every live/pending/enrolling/enrolled/releasing allocation. Before returning `may_delete:true`, the coordinator must retain a durable deletion barrier for that exact reservation UID so a new native enrollment cannot race between the response and the API DELETE. New preparations remain denied until actual reservation absence or explicit safe reconciliation of the failed deletion. A false result retains the reservation. API deletion uses current UID/RV preconditions, and no caller can turn Pod absence alone into native-zero/capacity release. This persistent barrier is required because the boolean response alone cannot hold a server mutex across the subsequent binder DELETE.

The server authenticates every method anew. It binds each fence to authenticated original binder identity, PodUID, current attempt, selected node/epoch and prepared generation. A different actor, Pod, attempt, request generation, authority namespace, node, maps, enrollment, ACK or driver epoch is denied. Fence IDs alone are not bearer authority. Normal UI/user Source endpoints never expose this interface. Root owns the Python implementation and any installation; Go transport/startup tests remain offline.
