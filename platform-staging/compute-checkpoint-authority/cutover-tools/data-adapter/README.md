## Failure and target-write boundary

Every phase saves exclusive UNKNOWN intent before RPC/pipe, then full successful reply or HOLD. No second mutation is permitted for an existing intent. Snapshot/transport lost reply means HOLD with targetMayHaveBeenWritten=false: they touch /work only. Before install RPC targetMayHaveBeenWritten becomes true conservatively and is durably recorded. Lost reply, error or failed result validation thereafter means target MAY contain partial/completed authority data; never retry install or reopen old writers automatically. Pre-dispatch gate/proof rejection has no install intent and leaves target flag false. No phase deletes, repairs, adopts or rolls back a partial target. Root must reconcile actual authoritative state.

Native snapshot/install code is delivered through short `python3 -` STDIN calls; full original protocol is loaded hash-exact, gate called, then original function invoked. No fake ACK or replacement implementation. Binary tar remains separate short exec loaders and uses existing validated stream; outputs/errors stay separate private files. All local adapter files are under exclusive0700 directory, intents0600.
