# Common SDK/addon/RTC wheelhouse qualification

Status: complete shared package closure passed isolated Python 3.12/3.13 installation and fresh-kernel fixtures; the notebook base-image matrix remains unqualified.

The wheelhouse contains 146 reviewed wheel files at 133 common package versions. It uses the exact new compute wheel from `ecca9028cf11c263f1753c4d01200ca753fcfce8`, JupyterLab 4.5.7 and Jupyter Collaboration 4.4.1, retaining the previously resolved Notebook 7.5.6 compatibility range. Separate binary wheels cover both interpreter ABIs at matching versions. The missing PyCRDT 0.13.0 CPython 3.12 wheel was fetched, and both ABI wheel hashes were independently matched to official PyPI release metadata. All files and the generated hashed requirements are recorded beside this document; binary artifacts remain outside Git.

Full assembly exposed legitimate nested vendor metadata in Bleach and Setuptools. The prior validator counted it as additional outer distributions and refused valid wheels. The regression failed before the fix and passed afterward: wheel identity now requires exactly one top-level METADATA record, nested records are ignored, and multiple top-level records still fail. All 13 release-runner tests passed. Hash checks, exact-version grouping, all-variant inventory, immutable base digest, clean/tagged source and RTC/addon gates remain intact.

The same generated requirements installed with no index/network access into isolated targets for Python 3.12.13 and 3.13.12. With global site packages disabled, both targets imported the SDK, JupyterLab, RTC and native extensions; required non-extra dependency metadata was consistent. All 21 SDK Python modules and five prebuilt addon assets matched source hashes in both targets.

Each target then ran separate owned fresh-kernel success and failure notebooks through Papermill, using explicit local kernelspecs selecting its interpreter and SDK path. Boolean, integer, float and string parameters preserved their types; saved inputs were unchanged and both successful and failed executed notebooks were retained. These were local controlled files, not a live student notebook or shared kernel. Initial fixture construction errors were corrected before passing evidence was recorded; they were not runtime qualification failures.

The structural base digests used only to exercise wheel validation were fixtures and are not included as release targets. No notebook image was built or deployed by this work, and no GPU was accessed. This common closure does not prove compatibility with every inherited ML/desktop base environment. Next, bind actual reviewed immutable bases, build all 12 variants from the same notebook source, run each base's pip/runtime checks, and qualify paired Hub/gateway/admin/addon behavior. Full release tags and production promotion remain gated.
