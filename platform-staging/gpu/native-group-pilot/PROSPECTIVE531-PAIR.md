Status: source qualified; not activated or hardware qualified.

`qualification_proposal.py` retains the existing single CPS5 proposal. Supplying
both `--peer-target-snapshot` and `--peer-target-snapshot-sha256` in the explicit
`prospective-candidate` render mode requests exactly two independently pinned,
fresh, stopped CPS operator targets: primary5 and peer20. No default preset,
production916/D48 policy, driver, MIG mode or live object changes.

The pair requires:

- Distinct normal Source workspaces, neutral owners, Pod names and PVCs. Both
  captured descriptors bind the same actual Source51f instance, original policy,
  sixteen-module source closure and complete retired authority.
- Explicit canonical operator members, with disjoint member sets. The normal
  reservation table has one row per canonical person; a larger allowance does
  not permit that person to reserve two workspaces. The same administrator may
  operate both records, but a second independently reviewed operator identity and
  legitimate entitlement are prerequisites. Do not fabricate aliases or reuse
  the student test identities.
- Exactly image531, disabled/unqualified5 and20 profiles, maximum two workspaces,
  25600 MiB total cap, 1024 MiB additional headroom and at least26624 MiB measured
  free memory. The measured GPU/boot/driver identity and no-MIG checks remain.
- Every existing terminal-history entry and all four configuration-authority
  references. The rendered acceptance still reports `hardware_qualified:false`
  and `live_applied:false`.

`prospective_source_qualification_workspace.py` accepts the same optional peer
path and raw pin. Its selected `--target-snapshot` may be either member of the
validated pair. It uses the existing genuine owning Source application and
normal WorkspaceService get/start/close methods; the administrator actor and
all registration/storage/identity checks remain. Starts continue to use normal
member entitlements and global reservations. Omitting the peer retains single5
behavior. Both CLIs remain inert without their explicit render/execute flag.

passed. Root must capture actual reviewed targets and complete the existing
