# Prospective CPS pair Gateway transition

`gateway_transition.py` produces inert forward and inverse CAS artifacts for the
Root-pinned fresh CPS5+20 pair. It performs no API, credential, file, workload,
Source, Hub or driver operations.

`forward_intent` accepts the prospective proposal, full original policy ConfigMap,
runtime Secret and Gateway Deployment, original Node configuration, and the exact
independently reviewed Root contract bytes/hash. It validates the real policy,
native group and qualification models. The original must be the D48 group mode;
the target must retain the full verified baseline history, physical epoch,
disjoint Root people, fixed profile ceilings, 531 workload and retained gate image.

Only the two trusted **disabled** qualification aliases may extend the catalog.
Ordinary profiles, global qualification and all other catalog fields remain exact.
Only the native modes, optional dynamic approval reader and policy hash change in the decoded runtime. Other runtime
fields and other Secret data entries remain exact. Gateway Deployment changes are the qualification rollout annotation and removal
of the exact owning dynamic approval heartbeat bootstrap when present. The exact
pinned dynamic-only approval-capture container is also removed; its server requires
the group runtime disabled by qualification mode. Retained container images,
credentials, other environment entries, volumes, resources and other fields remain unchanged.

`inverse_intent` recomputes that exact forward plan and compares all fresh current
object data/specs and ownership against it. It then produces inverse patches with
current UID, resource version and full data/spec tests, restoring the exact original
values. Any unrelated edit causes refusal instead of overwriting it.

These planners are useful for all three Node restoration phases: unstarted,
partial and complete. They do not independently prove a safe execution point.
Source and Hub forward/restoration operations, complete Node/physical custody,
normal Stop confirmation, actual immutable configuration/code readbacks and
coordinated application order remain mandatory. Do not apply these patches as a
standalone Gateway change. No live deployment or hardware qualification is claimed.

Validation on 16 October 2026: the focused Node/Gateway matrix passed **48 tests**.
The complete native-group pilot suite passed **679 tests and 851 subtests**, with
14 skips. These results are CPU evidence, not deployment or GPU acceptance.
