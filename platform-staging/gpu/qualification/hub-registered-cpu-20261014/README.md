# Registered CPU Hub adapter

The released adapter preserves the registered neutral-account boundary while
passing the trusted CPU image through the actual native configuration wrapper.
The existing operator image must be an immutable digest. CPU admission still
requires the central profile and retains all negative identity, resource and
image controls.

Both Hubs were updated to the exact qualified image using a reviewed image and
publisher-binding change. Gateway runtime changes covered only the two trusted
Hub image references. The unchanged gateway restarted; all four actual
components acknowledged the existing approval revision, policy and GPU epoch.
A separate new delivery journal completed, the old journals remain retained,
and the final actual native readback showed zero caps and charged bytes.

`receipt.json` records installed/source tests, remote image verification and
hashes of the private qualification, matching handover and native readbacks.
Those private files remain operator-only because they include cluster bindings
and operational records.

This is package and deployment evidence. Normal CPU HTTP lifecycle, human OAuth,
consumer release promotion and production acceptance remain separate gates.
