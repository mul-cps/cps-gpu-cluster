# V2 workspace mount admission

Status: live Kubernetes object boundary qualified; cross-group privacy and production handover remain open.

`platform-staging/chart/templates/workspace-mount-boundary.yaml` supplies two fail-closed policies and bindings. New/updated NFS PVs cannot expose `/`, `/mnt`, `/mnt/persistent1`, the V2 root or its CPS/CIT parents. V2 leaf PV creation requires the actual compute-controller identity and retained, RWX, source-bound claim metadata on the existing NFS server. Existing protected PV metadata/binding-UID updates may proceed only with unchanged NFS and claim name/namespace plus retained/source-bound metadata, allowing normal PV controller reconciliation without allowing data rebinding or Delete reclaim policy.

Direct Pod NFS mounts cannot expose those ancestors or any V2 group. Paths must be absolute without doubled slashes or dot/traversal components. Read-only flags and container subPath do not exempt broad mounts. The checks apply independently of server hostname/IP aliases. Ordinary sibling homes, dataset/scratch paths and other nonprotected NFS paths remain allowed. Existing inventory had no ancestor PV/direct Pod mounts for V2. The legacy V1 shared-home root still overlaps the legacy compute tree and is deliberately not described as isolated.

Before the rule, 36 forbidden cases were accepted by server dry run. Isolated policy clones then tested the matrix; live rules passed 52 operator requests, 10 actual-controller requests and two existing PV update checks. Cases cover parent/source/group paths, trailing/doubled slashes, traversal, alias names, read-only/subPath requests, ordinary sibling paths, source-bound positive bindings and namespace/server/reclaim-policy denials. Metadata update was allowed while changing the retained PV to Delete was rejected. No test Pod or PV was allocated by these dry runs.

The Rancher proxy ignored `kubectl --as`: SelfSubjectReview still reported the operator. Those apparent controller cases were discarded. Positive controller and crafted controller requests instead ran from a controlled restricted Pod using the real `cps-compute-controller` projected token and direct Kubernetes API; SelfSubjectReview confirmed the exact identity. The reusable `probe-workspace-mount-controller.py` requires that operator-controlled context, performs only server dry runs and must never be run on cluster runners for public PR code.

The live policies exactly match the Helm-rendered chart and show observed generation with no CEL warnings. Temporary clone policies/bindings, namespace and controller probe Pod were removed. Production gateway image and running user Pods were not changed.

This enforces Kubernetes NFS PV/direct-Pod paths, not all storage access. PVC authorization still depends on the gateway/Hub adapter, namespace RBAC and registered group binding. Only Longhorn CSI is currently installed; adding an NFS CSI driver requires equivalent enforcement. Userland NFS/RPC traffic and Pod egress must be qualified separately, because shared Unix UID 1000 alone does not isolate users who can reach NAS exports directly. Do not mark privacy, legacy migration or production group storage qualified from this matrix. Exact results are in `workspace-mount-boundary-report.json`.
